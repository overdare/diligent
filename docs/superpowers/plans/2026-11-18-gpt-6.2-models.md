# GPT-6.2 Models Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make GPT-6.2 Astra and Sol selectable and usable through both existing authentication paths.

**Architecture:** Extend the shared provider catalogs and Responses request builder. The TUI and external clients consume the existing model protocol without client-specific registration.

**Tech Stack:** Bun, TypeScript, bun:test.

**Spec:** The approved request is to add both models in this separate checkout, verify them, and update the consuming repository's submodule. API cards use 1,050,000 context tokens and 128,000 output tokens. Subscription cards use 272,000 context tokens for Astra and 500,000 for Sol. Both expose low, medium, high, xhigh, max reasoning, vision, and Fast mode. Standard short-context input/output/cache-read/cache-write rates per million tokens are 8/40/0.4/10 for Astra and 2/10/0.1/2.5 for Sol.

## Global Constraints

- Keep existing defaults, model classes, aliases, and previous models compatible.
- Use the shared protocol and public exports; do not add client-specific model registries.
- Keep reusable GPT-6.2 instructions at the beginning of input, omit unsupported temperature, and use 30-minute prompt cache options.
- Preserve the existing subscription Responses Lite HTTP/WebSocket and native compaction paths.

## Review Focus

- Both provider-qualified identities must resolve and appear in the protocol catalog.
- The TUI picker must offer both models and preserve max reasoning on selection.
- New API requests must preserve tools, reasoning, and user history with supported cache fields.
- Subscription requests must use the existing Lite transport, with instructions appearing exactly once.
- Older models must retain their existing instruction and temperature behavior.
