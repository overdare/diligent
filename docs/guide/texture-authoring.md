# Albedo authoring

The OVERDARE sidecar adds two thin native RPC adapters: `studiorpc_texture_prepare` and `studiorpc_texture_apply`. Both Web and TUI consume these through the existing tool protocol. There is no separate canvas, generic runtime texture subsystem, image-generation provider or frontend-specific editor.

Diligent chooses painting, existing images or generated artwork and owns prompts and references. Studio owns surface discovery, UV mapping, deterministic painting, source persistence, image publishing, binding, Undo, conflict checks and saving. The final game uses a published image and compact mapping parameters. Flat detail adds no scene instances or geometry.

Prepare accepts `targetGuid`, optional resolution (256, 512, 1024) and an optional complete version 1 plan. Omitting the plan inspects the saved document. Each plan has a base and a surface-to-layers map. Layers use sRGB byte colors, normalized rectangles and stable ids. The native response contains regions, physical dimensions, preview paths, missing image keys, prepare identity and target revision. It is read only with respect to the world, but writes staging files.

Apply accepts the prepare identity, revision, target, requestId and any missing image files or published image ids. Native publishing may return pending; resend the same arguments and requestId to obtain the result. `applied` means the final `ovdrassetid://` image was bound and saved. `applied_save_failed` means the same request should retry saving. An interrupted upload must be inspected before starting a new request. Neither a local PNG nor an accepted upload proves completion.

The native contract validates colors, rectangles, surfaces, layer ids, references and fonts again. Sidecar schemas provide earlier feedback and are not an authorization or integrity boundary. Native failures remain structured tool results; callers inspect status and code.

The opt-in dev shared-root adapter maps nested apply `images.*.filePath` inputs to the Studio host and prepare `guidePath`/`previewPaths` and apply `imagePath` back to the agent host. It preserves asset ids and request identity. Paths outside configured roots fail before calling Studio. This maps an existing shared filesystem; it does not copy files.

The existing `generate_image` remains selected-provider-bound. Standalone or HTTP MCP clients use their own image generator and pass its files to apply. No credentials are inferred from stored auth. Native plans never carry prompts, provider names or model settings.

See the bundled `texture-authoring` skill for the agent workflow. The native implementation and its running version remain authoritative for supported target and material combinations.

The first native version supports opaque Block Parts and 1..64 baked static MeshParts per ProceduralModel. Boxes expose six named faces and require face-split normals; call the existing `G.recompute_normals(mesh)` before `model.part`. Smooth box corner normals are rejected because vertex-stage face selection cannot identify their faces reliably. Other meshes expose one UV0 chart per stable recipe part name, require non-overlapping UV interiors, and accept at most 32,768 triangles per chart. Use the geometry recipe's `repack_uvs` before authoring a chart whose projections overlap. Chart dimensions are estimates for artwork sizing; curved charts do not provide named semantic faces.

The existing World albedo group has a 1024 maximum on Android and iOS, including mobile preview. Mipmaps and streaming remain enabled. The native summary distinguishes source size, allowed size and resident size, so inspect those before increasing an image's resolution.

An explicit base fill defines the painted color layer. `base.current` preserves plain Basic/Plastic colors; existing textured presets, legacy textures and custom material variants require an explicit fill or the saved authoring plan. Authoring new normal, roughness and metallic maps is outside this first version. The existing CPL material graphs add an atlas-coordinate function made from standard material nodes; their original Albedo samples, lighting, normal/roughness maps and physical material remain in the existing pipeline. Runtime uses the existing material instance, without a separate master material, second DMI or Custom HLSL. Atlas mode defaults off for existing objects. The native `Texture` read summary reports the final image, layout, document status and loaded/resident image dimensions when available. Internal binding/document properties are managed by the texture service. Clearing a managed `TextureId` through the existing instance edit path clears that binding and document.

Font size is a fraction of the full surface height. The text rectangle clips the output and centers it; it does not redefine that font-size unit. Inspect `TEXT_CLIPPED` before applying a label. A checker preview or `SOURCE_PREVIEW_UNAVAILABLE` warning means a published source has not been loaded for preview; apply still validates the actual source.
